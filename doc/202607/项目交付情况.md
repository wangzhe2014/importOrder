## 3. 核心完成情况

### 3.1 上传即返回

- `POST /api/import-tasks` 接收文件并生成 `task_id`、`trace_id`。
- 上传接口只负责流式接收文件、保存文件引用、创建空任务和投递异步规划事件。
- 后续行数统计、批次拆分、SKU 校验和批量写库均由 Worker 异步执行。

### 3.2 异步事件驱动

- 使用 `import_tasks` 保存任务状态。
- 使用 `event_queue` / Outbox 承接异步任务。
- Worker 消费 `ImportTaskCreated` 和 `ImportBatchCreated` 事件。
- 支持 DB fallback queue；生产推荐 Upstash Redis + BullMQ。

### 3.3 批次与幂等

- 默认 `1000 行/批`，10000 行拆分为 10 个处理单元。
- `claim_batch` 使用 CAS 认领批次，避免重复消费。
- `complete_batch` 从批次账本聚合任务进度，避免重试重复累计。
- 运单写入使用 `external_code + sku_code + line_no` 幂等 UPSERT。
- `recover_stale_batches` 支持 Worker 崩溃后的卡死批次恢复。

### 3.4 Supabase Storage 优化

- 生产文件存储使用 Supabase Storage 私有 bucket：`import-files`。
- 规划阶段只下载并解析原始文件一次。
- 规划阶段生成 `${task_id}/_planned.json.gz` 中间产物。
- 中间产物保存按 `unit_id` 切好的解析结果和任务级 SKU 校验输入。
- 批次处理优先复用 Worker 内存缓存或 `_planned.json.gz`，不再每批重复下载和重复解析原始 Excel。

### 3.5 批量校验与写库

- SKU 校验改为任务级批量校验。
- 数据库已执行 `validate_sku_codes` RPC，用于一次性批量查 SKU。
- 若 RPC 尚未迁移，代码会自动回退到并发分块查询。
- 写库按 500 行分块 UPSERT，避免逐行 INSERT。

### 3.6 错误定位

- 行级错误写入 `import_task_errors`。
- 错误包含行号、字段、脱敏原始值、错误码、英文错误原因和 `trace_id`。
- 支持错误分页查询和 CSV 导出。
- 少量错误行不会阻塞整批有效数据入库，任务最终可进入 `partial_success`。

### 3.7 可观测性

- Trace 事件覆盖上传、规划、批次开始、批次结束和降级事件。
- `batch_performance_log` 记录 parse、rule、validate、insert、total 阶段耗时。
- 首页已内嵌导入监控和 Trace 检索。
- `/monitor`、`/traces`、`/import/:taskId` 保留兼容访问。

## 5. 生产部署说明

### 5.1 必要环境变量

```env
NEXT_PUBLIC_SUPABASE_URL=your_supabase_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key
QUEUE_BACKEND=auto
UPSTASH_REDIS_URL=rediss://default:password@host:6379
IMPORT_BATCH_SIZE=1000
WORKER_CONCURRENCY=2
SKU_CHECK_TIMEOUT_MS=3000
IMPORT_TASK_CACHE_TTL_MS=1800000
IMPORT_TASK_CACHE_MAX_ENTRIES=4
UPLOAD_STORAGE_BACKEND=supabase
SUPABASE_STORAGE_BUCKET=import-files
```

### 5.2 Supabase 初始化

已执行的 SQL 脚本：

```text
supabase/init.sql
supabase/migration_async_v2.sql
supabase/storage_import_files.sql
```

关键对象：

- `import_tasks`
- `import_task_batches`
- `import_task_errors`
- `event_queue`
- `event_outbox`
- `batch_performance_log`
- `trace_events`
- `sku_master`
- `validate_sku_codes` RPC
- `import-files` 私有 Storage bucket

### 5.3 Worker 部署

Worker 不能依赖 Vercel Serverless 常驻运行。生产应部署到 Railway、Render、Fly.io、容器服务或虚拟机，启动命令：

```bash
npm run worker
```

Web 服务和 Worker 必须使用同一套 Supabase、Storage 和队列环境变量。

## 6. 验收路径

1. 打开生产环境 URL：https://import-order-olive.vercel.app/
2. 上传 Excel 文件，确认接口返回 `task_id` 和 `trace_id`。
3. 在导入监控中查看任务进入 `processing`。
4. 在任务详情页查看 processed、success、failed 和错误明细。
5. 用 `trace_id` 在 Trace 检索中查看链路事件。
6. 在 Supabase Storage `import-files` bucket 中确认原始文件和 `_planned.json.gz` 中间产物。
7. 执行 `npm run seed` 和 `npm run loadtest`，用真实结果更新 `压测报告.md`。

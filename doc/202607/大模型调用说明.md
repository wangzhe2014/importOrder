# 大模型调用说明

## 1. 使用范围

本项目中的大模型能力仅用于“AI 辅助生成解析规则”，不参与 10,000 行异步导入主链路的成功判定。

导入压测使用已确认的规则，压测指标只统计文件上传、任务创建、Worker 规划、批次处理、SKU 校验和批量写库。大模型调用耗时不计入 10,000 单/分钟目标。

## 2. 调用入口

| 项目 | 内容 |
|---|---|
| API 路由 | `POST /api/generate-rule` |
| 源码位置 | `src/app/api/generate-rule/route.ts` |
| 调用阶段 | 用户上传文件并抽取原始结构后，点击 AI 生成规则 |
| 输出结果 | `ParsingRule`、`ai_metadata`、`hit_cache`、可选 `warning` |
| 主链路依赖 | 否 |

请求输入为已经抽取出来的文件结构摘要，而不是直接把原始文件交给模型：

```ts
type ParsedFilePayload = {
  type: 'excel' | 'word' | 'pdf'
  fileName?: string
  sheets?: { name: string; data: string[][] }[]
  lines?: string[]
}
```

## 3. 环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `LLM_API_KEY` | 大模型 API Key。未配置时不调用模型，直接使用本地启发式规则生成 | 无 |
| `LLM_BASE_URL` | OpenAI-compatible API Base URL | `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 模型名称 | `deepseek-chat` |
| `LLM_TIMEOUT_MS` | 大模型调用超时时间 | `20000` |

示例：

```env
LLM_API_KEY=your_llm_api_key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_TIMEOUT_MS=20000
```

真实密钥必须配置在服务端环境变量中，不得提交到 Git 仓库。

## 4. 调用方式

接口使用 OpenAI-compatible `chat/completions`：

```text
POST ${LLM_BASE_URL}/chat/completions
Authorization: Bearer ${LLM_API_KEY}
Content-Type: application/json
```

请求体关键参数：

```json
{
  "model": "deepseek-chat",
  "messages": [
    { "role": "system", "content": "规则生成系统提示词" },
    { "role": "user", "content": "文件名、文件类型、样本数据、demos 参考样本摘要" }
  ],
  "temperature": 0.1,
  "response_format": { "type": "json_object" }
}
```

模型必须返回纯 JSON，核心结构如下：

```json
{
  "name": "规则名称",
  "structure_type": "standard",
  "config": {
    "header_row_index": 0,
    "data_start_row_index": 1,
    "column_mappings": {
      "external_code": "外部编码",
      "store_name": "收货门店",
      "sku_code": "SKU编码",
      "sku_quantity": "SKU数量"
    }
  },
  "ai_metadata": {
    "sku_code": {
      "status": "confident",
      "reason": "样本表头包含 SKU编码"
    }
  }
}
```

## 5. Prompt 约束

系统提示词要求模型扮演物流导入系统的解析规则专家，并限制输出为纯 JSON。

支持的结构类型：

- `standard`：标准表格
- `matrix`：门店/日期在列头的矩阵转置
- `card`：多段卡片式记录
- `free_text`：Word/PDF 自由文本

目标字段：

- `external_code`
- `store_name`
- `receiver_name`
- `receiver_phone`
- `receiver_address`
- `sku_code`
- `sku_name`
- `sku_quantity`
- `sku_spec`
- `remark`

允许生成的规则配置必须符合系统 `ParsingConfig`，例如：

- `header_row_index`
- `data_start_row_index`
- `data_end_marker`
- `column_mappings`
- `merge_sheets`
- `meta_extractors`
- `group_by_field`
- `group_fill_fields`
- `store_columns_start`
- `store_columns_end`
- `sku_fields_mapping`
- `card_start_pattern`
- `card_receiver_offsets`
- `free_text_receiver_patterns`
- `free_text_sequence_item`

## 6. 防失败与降级策略

大模型不是必需依赖。以下情况会自动回退到本地启发式规则生成：

1. 未配置 `LLM_API_KEY`。
2. 大模型接口超时。
3. 大模型 HTTP 返回非 2xx。
4. 模型返回内容不是合法 JSON。
5. 返回 JSON 缺少 `config`。
6. 生成规则无法解析当前样本。

回退时接口仍返回可用规则，并附带 `warning`：

- `AI 服务调用失败，已使用本地启发式规则生成。`
- `未配置 LLM_API_KEY，已使用本地启发式规则生成。`

## 7. 结果校验

模型返回后，系统不会直接信任结果，而是执行以下校验：

1. 解析 JSON 内容。
2. 标准化 `structure_type`。
3. 标准化 `ParsingConfig`。
4. 使用现有 V2 规则引擎对当前样本试解析。
5. 使用 `validateRow` 检查解析结果是否有可用行。
6. 不可用则回退到本地启发式规则。

这保证 AI 只辅助生成规则，不绕过既有规则引擎，也不会成为导入成功的必要条件。

## 8. 安全说明

- 不把 `LLM_API_KEY` 写入前端代码。
- 不把真实密钥提交到 Git。
- 只把样本结构摘要传给模型，不直接上传 Supabase service role key、数据库连接串或队列连接串。
- AI 生成规则需用户确认后才用于解析和导入。
- 异步导入主链路不调用大模型，避免模型故障影响批量下单能力。

## 9. 与考试要求的关系

考试要求说明：大模型能力为可选加分项，只能辅助错误摘要或规则生成，不得成为导入主链路成功的必要条件。

本项目符合该要求：

- AI 只参与规则生成。
- 用户确认规则后才执行解析。
- 压测使用已确认规则。
- 大模型不可用时系统仍可通过本地启发式规则生成继续工作。
- 10,000 行压测链路不依赖大模型。
